## 一、总体架构与五层模块划分

TxtSql 采用自底向上清晰解耦的**五层分层架构**，核心代码位于 `txtsql/` 目录下，共 **19 个模块、8,325 行 Python 代码**，零第三方 SQL 解析库依赖（仅 Excel `.xlsx` 导入/导出可选使用 `openpyxl`，桌面端使用标准库 `tkinter`）。

```
┌──────────────────────────────────────────────────────────────────────┐
│ 1. 用户接口层（UI & Adapters）                                        │
│    cli.py (交互式 REPL)   │   gui.py + gui_controller.py (Tkinter GUI)│
├──────────────────────────────────────────────────────────────────────┤
│ 2. 会话编排与结构化接口层（Orchestration & Result）                   │
│    engine.py: Database(data_dir, enable_optimizations)               │
│    result.py: QueryResult (kind, columns, rows, plan, tokens, ast)   │
├──────────────────────────────────────────────────────────────────────┤
│ 3. 语言解析与抽象语法树层（Frontend Compiler）                        │
│    lexer.py (词法分析) ──▶ parser.py (递归下降) ──▶ ast.py (AST节点)   │
├──────────────────────────────────────────────────────────────────────┤
│ 4. 查询优化与执行剖析层（Optimizer, Executor & Plan）                 │
│    optimizer.py (谓词下推/隐式连接重写/等值键)   plan.py (执行计划树) │
│    executor.py (QueryExecutor)    evaluator.py (三值逻辑表达式求值)   │
│    io_handlers.py (.xlsx / .csv / .tsv 导入与导出)                   │
├──────────────────────────────────────────────────────────────────────┤
│ 5. 纯文本存储与索引层（Storage & Secondary Index）                    │
│    storage.py (StorageEngine / Table / 指纹缓存 / CHECK / 快照事务)  │
│    index.py (Hash + bisect 混合二级索引)   types.py   exceptions.py   │
└──────────────────────────────────────────────────────────────────────┘
```

## 二、核心 SQL 语法（EBNF 摘要）

```ebnf
<statement>    ::= <create_table> | <drop_table> | <create_index> | <drop_index>
                 | <insert> | <update> | <delete> | <select_or_union>
                 | <import_stmt> | <show_stmt> | <describe_stmt>
                 | <explain_stmt> | <check_stmt> | <tx_stmt>

<create_table> ::= CREATE TABLE [IF NOT EXISTS] <id> '(' <col_def> (',' <col_def>)* ')'
<create_index> ::= CREATE INDEX [IF NOT EXISTS] <id> ON <id> '(' <id> ')'
<drop_table>   ::= DROP TABLE [IF EXISTS] <id>
<drop_index>   ::= DROP INDEX [IF EXISTS] <id>
<insert>       ::= INSERT INTO <id> ['(' <id_list> ')'] (VALUES <row_list> | <select_or_union>)
<update>       ::= UPDATE <id> SET <id> '=' <expr> (',' <id> '=' <expr>)* [WHERE <expr>]
<delete>       ::= DELETE FROM <id> [WHERE <expr>]

<select_core>  ::= SELECT [DISTINCT] <select_list>
                   FROM <table_src> (',' <table_src>)* (<join_clause>)*
                   [WHERE <expr>]
                   [GROUP BY <col_ref> (',' <col_ref>)*]
                   [HAVING <expr>]
<join_clause>  ::= [NATURAL] [INNER | LEFT [OUTER] | RIGHT [OUTER] | FULL [OUTER] | CROSS]
                   JOIN <table_src> [ON <expr> | USING '(' <id_list> ')']
<select_tail>  ::= [ORDER BY <col_ref> [ASC|DESC] (',' <col_ref> [ASC|DESC])*]
                   [LIMIT <int>] [OFFSET <int>] [INTO OUTFILE <string>]
<union>        ::= <select_core> (UNION [ALL] <select_core>)+ <select_tail>

<explain_stmt> ::= EXPLAIN [ANALYZE] <select_or_union>
<show_stmt>    ::= SHOW (TABLES | INDEXES [FROM <id>])
<check_stmt>   ::= CHECK TABLE <id>
<tx_stmt>      ::= (BEGIN | COMMIT | ROLLBACK) [TRANSACTION]
```

表达式优先级由低到高为：`OR` < `AND` < `NOT` / `NOT EXISTS` < 比较与谓词（`=`, `<>`, `!=`, `>`, `<`, `>=`, `<=`, `IS [NOT] NULL`, `[NOT] IN`, `[NOT] BETWEEN`, `[NOT] LIKE`, `ANY`/`ALL`） < `+` `-` < `*` `/` < 一元正负、括号、标量子查询、聚合调用与字面量/列引用。

## 三、存储格式与数据语义设计

### 1. 纯文本文件布局

每个数据目录相互独立（`Database(data_dir)`），无全局 `os.chdir()` 副作用：

- `metadata.txt`（TSV）：每行一张表，格式为 `table_name \t col_count \t col1 \t type1 \t ...`；
- `indexes.txt`（TSV）：每行一个二级索引，格式为 `index_name \t table_name \t column_name`；
- `<table_name>.txt`（TSV，使用 `csv.QUOTE_ALL`）：保存每行记录，字符串内的制表符、换行与引号自动转义往返。

### 2. `NULL` 与空字符串精确区分

- 数据库内部以 `None` 表示 SQL `NULL`，序列化至 TSV 时写入哨兵 `\N`；
- `STRING` 值中的字面反斜杠 `\` 写入前转义为 `\\`，读取时反转义还原，从而保证空字符串 `''` 与字面量 `'\N'` 均不会与 SQL `NULL` 混淆（同时兼容旧版 `NUMBER` 列空字段视作 `NULL` 的历史文件）。
- 全部元信息重写、`UPDATE`、`DELETE` 及 `ROLLBACK` 均采用 `tempfile.mkstemp()` + `os.replace()` 原子替换写盘，避免写半截损坏文件。

### 3. SQL 三值逻辑（3VL）

`evaluator.py` 严格实现 `True` / `False` / `None(UNKNOWN)` 三值真值表：

- 任意 `NULL` 参与比较（`=`, `<>`, `<`, `>` 等）或算术（`+`, `-`, `*`, `/`）均传播为 `None`；
- `AND` 遵循短路与（`False AND NULL -> False`），`OR` 遵循短路或（`True OR NULL -> True`），`NOT(NULL) -> None`；
- `WHERE` / `HAVING` 过滤时通过 `to_bool()` 将 `UNKNOWN` 折叠为 `False`；`ORDER BY` 排序始终将 `NULL` 置于末尾。

## 四、查询优化、二级索引与执行可视化机制

### 1. 混合二级索引与文件指纹缓存

- `ColumnIndex` 同时维护 `hash_map: dict[Decimal | str, list[int]]` 与排序键列表 `(sorted_keys, sorted_row_ids)`：
  - 等值 `=` 与 `IN (...)` 通过哈希字典在 $O(1)$ 定位候选行号；
  - 范围查询 `>`、`>=`、`<`、`<=`、`BETWEEN` 通过 `bisect_left` / `bisect_right` 在 $O(\log N)$ 切出区间行号，并合并同一列上的多条范围合取条件（如 `grade > 10 AND grade <= 25`）；
  - 严格跳过 `NULL` 键并在检测到类型不兼容时安全回退全表达式求值，保证 `TypeMismatchError` 语义与未优化路径 100% 一致。
- `StorageEngine` 对每个表记录 `(st_mtime_ns, st_size)` 指纹：SQL DML 主动失效缓存，外部记事本/脚本修改 `.txt` 后下次查询自动感知失效并重建索引。

### 2. 多阶段查询优化器（`optimizer.py`）

1. **外连接安全的谓词下推**：遍历 `JOIN` 链计算可能产生 `NULL` 填充的别名集合（`LEFT` 保护右表、`RIGHT` 保护所有已积累左表、`FULL` 保护两侧；`INNER`/`CROSS`/逗号 `FROM` 皆可下推），仅对非受保护侧且不含子查询/聚合的单表合取谓词实施扫描前下推（可再次命中该表的 `IndexScan`）。
2. **隐式逗号连接重写**：将 `FROM a, b WHERE a.id = b.id` 拆解为合成 `INNER JOIN`（无等值条件则为 `CROSS JOIN`），避免先在内存构造 $M \times N$ 笛卡尔积。
3. **内存 Hash Join**：从 `ON`、`USING`、`NATURAL` 提取等值连接键在右表构建哈希桶（跳过 `NULL` 键），左表线性探测后校验残余非等值 `ON` 条件并处理 `matched_right` 集合以支持 `LEFT`/`RIGHT`/`FULL` 外连接。

### 3. `EXPLAIN [ANALYZE]` 与白盒可视化

- `EXPLAIN` 静态推导完整物理/逻辑算子树（`TableScan` / `IndexScan` / `Filter` / `HashJoin` / `NestedLoopJoin` / `GroupAggregate` / `Having` / `Project` / `Distinct` / `Sort` / `LimitOffset` / `Union`）；
- `EXPLAIN ANALYZE` 实时执行并在各算子节点注入 `rows_in`、`rows_out`、选择率与 `time_ms`；
- GUI 层通过 `gui_controller.py` 与 `gui.py` 解耦渲染出 `tk.Canvas` 算子流水线视图（卡片色彩区分优化类型、边标出流向行数、底部按耗时占比绘制进度条）、指标明细树以及词法 `Token` 流和可折叠 `AST` 树。

## 五、纯文本完整性审计与会话快照事务

- **文本审计（`CHECK TABLE`）**：面向纯文本易被外部程序意外改坏的特点，扫描目标 `.txt` 文件逐行验证列数匹配度及 `NUMBER` 字段 `Decimal` 合法性，输出精确 1-based 错误行号。
- **快照事务（`BEGIN`/`COMMIT`/`ROLLBACK`）**：开启事务时快照 `metadata.txt`、`indexes.txt` 及各已知表 TSV 字节流；`ROLLBACK` 时删除事务内新建表文件、原子还原原表/元数据/索引并清空全部缓存。
