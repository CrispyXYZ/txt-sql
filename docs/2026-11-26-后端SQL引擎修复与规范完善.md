## 一、背景与设计决策

在清理并提交 `dev` 工作区积压的多表查询、算术表达式与子查询改动前，我们对后端全链路进行了代码审查，并与项目负责人确认了以下核心设计规范：

1. **严格区分空字符串 `''` 与 `NULL`（采用 `\N` 哨兵 + 反斜杠转义）**：
   - 在 `storage.py` 中以 `\N` 作为 SQL `NULL` 哨兵，字符串中的反斜杠统一转义为 `\\`，所有字段通过 `csv.QUOTE_ALL` 写入 TSV。由此彻底解决原实现中 `''` 与 `NULL` 混同、以及字面量 `\N` 冲突的问题。
2. **`TRUE` / `FALSE` 等价为数值 `1` / `0`**：
   - 在维持 `STRING` / `NUMBER` 双类型体系的前提下，将 `TRUE`、`FALSE` 统一解析并求值为 `NUMBER`（`Decimal('1')` / `Decimal('0')`），允许参与算术运算与数值比较、可写入 `NUMBER` 列；写入 `STRING` 列或与 `STRING` 比较时抛出 `TypeMismatchError`。
3. **补全半成品关键字 `EXISTS` 与 `UNION`**：
   - 消除 `lexer.py` / `parser.py` 中的未完成状态，完整实现 `EXISTS` / `NOT EXISTS`（含关联外层行引用）及 `UNION` / `UNION ALL`。

## 二、修复的 Bug 与 SQL 规范缺陷清单

### 1. 词法分析器（`txtsql/lexer.py`）
- **消除 `TokenType` 枚举值碰撞**：将 `TYPE_STRING = 'TYPE_STRING'`、`TYPE_NUMBER = 'TYPE_NUMBER'` 与字面量 `STRING`、`NUMBER` 分离，防止类型关键词与值字面量在 `StrEnum` 下互相别名覆盖。
- **未闭合字符串报错**：`read_string()` 在到达文件末尾仍未闭合单引号时抛出 `SqlSyntaxError`。
- **支持标准单引号转义 `''`**：如 `'O''Brien'` 正确解析为 `"O'Brien"`。
- **支持 `!=` 不等号与 `--` 单行注释**：补齐常见 SQL 写法，消除非法字符报错。

### 2. 语法分析器与 AST（`txtsql/parser.py`, `txtsql/ast.py`）
- **强制尾部 `EOF` 校验**：`Parser.parse()` 在消费可选分号 `;` 后强制校验 `EOF`，彻底修复尾随非法语句/碎片被静默忽略的问题（例如多表 `ORDER BY emp.id ASC` 曾被静默截断）。
- **修正 `INTO OUTFILE` 与分号顺序**：将 `INTO OUTFILE` 移至分号前解析，阻止 `SELECT ...; INTO OUTFILE ...` 非法通过。
- **支持限定列名与完整聚合语法**：
  - `GROUP BY`、`ORDER BY`、聚合参数均支持 `table.col`（`ColumnExpression`）。
  - 新增 `AggregateExpression` 与 `ExistsExpression`、`UnionStatement`。
  - 聚合函数不再强制要求 `AS` 别名，支持 `MAX(salary) - MIN(salary)` 等聚合算术表达式及 `HAVING COUNT(*) > 1` 直接聚合引用。
  - 严格校验 `WHERE` 中禁止聚合函数、`SELECT *` 禁止与 `GROUP BY` 混用、`CREATE/INSERT/IMPORT` 禁止重复列名、`LIMIT`/`OFFSET` 必须为非负整数（拒绝负数与小数）。
- **支持 `INSERT`/`UPDATE` 负数字面量**，以及 `(expr) IS [NOT] NULL` 运算符优先级修正。

### 3. 存储引擎（`txtsql/storage.py`）
- **严格区分 `''` 与 `NULL`**：实现 `\N` 哨兵、`\\` 转义与 `csv.QUOTE_ALL` 存储。
- **修复多行字符串行数统计错误**：`Table.count_rows()` 改用 `csv.reader` 解析记录而非按 `\n` 换行数计数。
- **补齐原子性与类型校验**：
  - `drop_table()` 使用临时文件 + `os.replace` 原子更新 `metadata.txt`。
  - `Table.insert_rows()` 在写入前统一完成全批次类型校验，避免多行 `INSERT` 中途报错留下半写数据。
  - `Table.update()` 直接校验类型并返回受影响行数；`Table.delete(where=None)` 改用原子写清空；`Table._dedup()` 使用类型安全去重键。

### 4. 表达式求值器（`txtsql/evaluator.py`）
- **SQL 三值逻辑（3VL）**：`_compare()` 对含 `NULL` 的比较返回 `None`（`UNKNOWN`），`LogicalExpression` 遵循三值真值表（如 `FALSE AND NULL -> False`、`TRUE OR NULL -> True`、`FALSE OR NULL -> None`）。
- **修复 `IN` / `NOT IN` / `ANY` / `ALL` 边界缺陷**：
  - 正确处理空子查询（`IN`/`ANY` 为 `False`，`NOT IN`/`ALL` 为 `True`，包括左值为 `NULL`）。
  - 正确处理子查询含 `NULL` 时的 `NOT IN` / `ALL`（如 `20 NOT IN (10, NULL)` 返回 `UNKNOWN` 而非 `True`）。
  - 校验子查询必须恰好返回 1 列，多列子查询抛出 `EngineError`。
- **修复 `TRUE`/`FALSE` 与 `STRING` 的不对称比较**：统一按照数值 `1`/`0` 处理，跨类型比较统一抛出 `TypeMismatchError`。
- **单表非法表前缀校验与关联子查询支持**：单表查询遇到无效 `bogus.col` 报错；支持嵌套/关联子查询通过 `outer_row` 访问外层列。

### 5. 执行器、编排层与 CLI（`txtsql/executor.py`, `txtsql/engine.py`, `txtsql/cli.py`）
- **修复 `USING`/`NATURAL` JOIN 在 `RIGHT`/`FULL JOIN` 下的列名解析**：合并共享列直接暴露无前缀 coalesced 列名，确保 `SELECT id`、`WHERE id = ...`、`ORDER BY id` 在右/全连接下不丢失值也不报歧义。
- **支持 `ORDER BY` 按未投影列及 `table.col` 排序**：保留 `(raw_row, proj_row)` 对，优先解析投影别名，其次解析原始/分组列。
- **统一分组路径**：无聚合函数的 `GROUP BY`（如 `SELECT dept FROM emp GROUP BY dept`）现在正确分组；空表无 `GROUP BY` 聚合（如 `SELECT COUNT(*), SUM(x) FROM empty_t`）返回单行结果；`SUM`/`AVG` 传入非数值列抛出 `TypeMismatchError`。
- **修复 `SELECT DISTINCT` 去重键冲突**：区分 `None` 与 `'None'`、数字与数字字符串。
- **修复 `DELETE`/`UPDATE` 的 `WHERE` 无法执行子查询**：注入 `subquery_exec` 与表限定校验。
- **校验 `FROM`/`JOIN` 重复表名/别名冲突**；显式多列投影同名冲突自动保留 `table.col` 限定名。
- **实现 `execute_union()`**：支持 `UNION`（去重）、`UNION ALL`、多分支链式、列数一致性校验、首分支列名继承及顶层 `ORDER BY`/`LIMIT`/`OFFSET`/`INTO OUTFILE`。
- **完善 `IMPORT`**：空列推断为 `Types.STRING`，导入失败时自动回滚清理新表。
- **修复 `CLI` 表格渲染**：`print_table()` 将 `None` 显示为空白而非字符串 `'None'`。
