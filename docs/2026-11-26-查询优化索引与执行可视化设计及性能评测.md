## 一、核心创新点与技术架构

1. **纯文本二级索引与文件感知缓存（[index.py](file:///home/crispyxyz/PycharmProjects/txt-sql/txtsql/index.py)、[storage.py](file:///home/crispyxyz/PycharmProjects/txt-sql/txtsql/storage.py)）**
   - 新增 SQL 语法：`CREATE INDEX [IF NOT EXISTS] idx ON tbl (col)`、`DROP INDEX [IF EXISTS] idx`、`SHOW INDEXES [FROM tbl]`；索引元信息持久化于纯文本 `indexes.txt`。
   - 内存中构建 `ColumnIndex` 混合结构：**Hash 字典**支持 `=` / `IN` 的 $O(1)$ 点查，**有序键值数组 + `bisect`** 支持 `>` / `>=` / `<` / `<=` / `BETWEEN` 的 $O(\log N)$ 范围查，完整遵循 `Decimal`/`str` 类型语义与 SQL `NULL` 语义。
   - 基于 `(st_mtime_ns, st_size)` 文件指纹实现表行缓存与自动失效，既减少重复反序列化开销，又保证用户在外部编辑器直接修改 `.txt` 后索引与缓存能自动感知重建；DML 与 `DROP TABLE` 同步维护/级联清理。

2. **多阶段关系查询优化器（[optimizer.py](file:///home/crispyxyz/PycharmProjects/txt-sql/txtsql/optimizer.py)、[executor.py](file:///home/crispyxyz/PycharmProjects/txt-sql/txtsql/executor.py)）**
   - **Hash Join（哈希连接）**：拆解 `ON` 顶层 `AND` 合取式或 `NATURAL`/`USING` 公共列，提取等值键在右表构建哈希桶，将等值连接从嵌套循环的 $O(M \times N)$ 降至 $O(M + N)$，同时兼容复合键、重复键、残余非等值过滤、`NULL` 不匹配及 `INNER`/`LEFT`/`RIGHT`/`FULL` 外连接。
   - **外连接安全的谓词下推（Predicate Pushdown）**：识别 `LEFT`/`RIGHT`/`FULL` 中的 null-producing 侧并阻止不安全下推，仅将安全单表合取条件（不含子查询/聚合）下推到源表扫描前执行，并与单表 `IndexScan` 联动。
   - **隐式逗号连接重写（Implicit Join Rewrite）**：将 `FROM a, b WHERE a.id = b.id` 自动重写为合成 `INNER JOIN`（走 Hash Join），避免先膨胀构造 $M \times N$ 笛卡尔积。
   - 提供 `Database(..., enable_optimizations=True|False)` 开关，支撑“优化开启 vs 关闭”结果等价性验证与定量基准对比。

3. **白盒执行剖析与 GUI 交互可视化（[plan.py](file:///home/crispyxyz/PycharmProjects/txt-sql/txtsql/plan.py)、[gui.py](file:///home/crispyxyz/PycharmProjects/txt-sql/txtsql/gui.py)）**
   - 新增 `EXPLAIN [ANALYZE] <SELECT | UNION>`：支持静态计划生成与运行时 `rows_in` / `rows_out` / `Selectivity` / `Time(ms)` 采集；`QueryResult` 同步携带 `PlanNode` 树、词法 `Token` 流与递归 `AST` 树。
   - GUI 新增 **`🔍 剖析计划 (Ctrl+E)`**、左侧表浏览器 `⚡ 索引` 节点、第 5 套示例模板，以及底部第 5 页签 **「执行计划与可视化」**：
     - **算子流水线视图（`tk.Canvas`）**：绘制树状算子卡片、优化徽章（`⚡ Index Scan` / `⚡ Hash Join` / `⚡ Predicate Pushdown`）、行数衰减箭头与耗时占比条；
     - **算子指标明细（`ttk.Treeview`）**：逐层展示输入/输出行数、选择率与阶段耗时；
     - **词法 Token 与 AST 透视**：展示自研 `Lexer` 记号流与 `Parser` 抽象语法树，直观体现全栈自研内核。

4. **纯文本完整性审计与会话级快照事务（[storage.py](file:///home/crispyxyz/PycharmProjects/txt-sql/txtsql/storage.py)）**
   - `CHECK TABLE tbl`：扫描 `.txt` 数据文件，校验缺文件、列数与 Schema 不符、非法 `NUMBER` 格式并精确报出 1-based 行号。
   - `BEGIN [TRANSACTION]` / `COMMIT [TRANSACTION]` / `ROLLBACK [TRANSACTION]`：基于目录快照实现 DML/DDL/索引变更原子回滚，并在 GUI 底部状态栏实时提示 `[事务中]`。

## 二、自动化性能基准实测数据

测试脚本：[benchmarks/run_benchmark.py](file:///home/crispyxyz/PycharmProjects/txt-sql/benchmarks/run_benchmark.py)（在隔离临时目录运行，所有场景均已断言优化开启与关闭返回结果完全一致）。

运行命令：

```bash
.venv/bin/python benchmarks/run_benchmark.py
```

实测结果：

| 实验场景 | 数据规模 | 未优化耗时 (ms) | 优化后耗时 (ms) | 加速比 | 核心优化机制 |
|---|---|---|---|---|---|
| 等值连接 (`JOIN`) | 1,000 × 1,000 行 | 2220.82 | 3.65 | **608.1x** | Hash Join ($O(M+N)$) |
| 等值连接 (`JOIN`) | 2,000 × 2,000 行 | 9154.34 | 8.92 | **1026.4x** | Hash Join ($O(M+N)$) |
| 索引等值点查 (`=`) | 10,000 行 | 15.73 | 0.16 | **98.2x** | Hash 二级索引 (`IndexScan`) |
| 索引范围查询 (`BETWEEN`) | 10,000 行 | 24.88 | 0.23 | **106.9x** | 有序数组二分 (`bisect`) |
| 逗号连接 + 单表过滤 | 1,200 × 1,200 行 | 7294.73 | 2.83 | **2580.8x** | 索引 + 谓词下推 + 隐式连接重写 + Hash Join |
