## 一、重构动因

在上一轮完成后端 SQL 全链路修复后，代码结构仍存在 4 处阻碍后续 Tkinter GUI 接入与长期维护的架构摩擦：

1. **隐式全局工作目录耦合**：`storage.py` 硬编码相对路径 `'metadata.txt'` 和 `f'{name}.txt'`，引擎状态绑定在进程 `os.getcwd()` 上，导致 GUI 目录切换与多库隔离只能依赖修改全局 cwd。
2. **返回契约丢失结构信息**：`execute_sql()` 返回 `list[RowDict] | int | None`，`SELECT` 查出 0 行时丢失表头 `columns`，`INSERT` 丢失插入行数，迫使 CLI（及未来 GUI）用 `isinstance` 猜测类型。
3. **执行层与导入导出/存储查询职责重叠**：`executor.py` 直接耦合 `openpyxl`/`csv`；`storage.Table.select()` 保留了未被执行器使用的重复过滤/排序/去重代码。
4. **求值层跨模块私有依赖与参数透传**：`executor.py` 导入了 `evaluator.py` 的 4 个私有函数，表达式求值层层传递 6 个散乱上下文参数，`parser.py` 与 `executor.py` 各自维护一套相同的 AST 聚合检测逻辑。

## 二、四项深化优化内容

### 1. 目录作用域隔离（`txtsql/storage.py`, `txtsql/engine.py`, `txtsql/executor.py`）
- 新增 `StorageEngine(data_dir='.')`：将 `metadata.txt` 与 `<table_name>.txt` 的定位、创建、原子重写（临时文件均创建于 `data_dir` 内）全部收口到指定数据目录。
- `Table` 增加 `data_dir` 参数与 `file_path: Path` 属性；保留 `select()` 无参兼容别名委托给 `read_rows()`，移除 `Table.select()` 中已被执行器取代的冗余过滤/排序/去重死代码。
- 在 `engine.py` 新增 `Database(data_dir='.')` 会话类（提供 `execute(sql)`、`list_tables()`、`get_table(name)`、`data_dir`），CLI 与未来 GUI 均可直接持有一个或多个独立 `Database` 实例，不再修改进程 `os.getcwd()`。
- 保留 `execute_sql(sql, data_dir='.')` 与模块级 `storage.*` 函数向后兼容。

### 2. 结构化执行结果对象（`txtsql/result.py`, `txtsql/executor.py`, `txtsql/cli.py`, `txtsql/__init__.py`）
- 新增 `StatementKind`（`SELECT`, `UNION`, `INSERT`, `UPDATE`, `DELETE`, `DDL`, `SYSTEM`, `IMPORT`, `EXPORT`）与不可变 `QueryResult`（含 `kind`、`columns`、`rows`、`affected_rows`、`message`、`is_tabular`、`to_legacy()`）。
- 即使 `SELECT` / `UNION` 返回 0 行，`QueryResult.columns` 仍完整保留表头信息，直接满足未来 GUI 表格渲染空结果集表头的需求。
- `INSERT` 同样准确返回 `affected_rows`；`cli.py` 改为直接基于 `Database` 与 `QueryResult` 分发渲染。
- `txtsql/__init__.py` 公开导出 `Database`、`execute_sql`、`QueryResult`、`StatementKind`、`TxtSqlError`。

### 3. 剥离外部文件 I/O，精简执行器（`txtsql/io_handlers.py`, `txtsql/executor.py`）
- 新增 `txtsql/io_handlers.py`：独立承接 `.xlsx` / `.csv` / `.tsv` 导出（`export_rows`）与 Excel 导入及类型推断（`read_excel_table`）。
- 将 `executor.py` 重构为基于 `StorageEngine` 的 `QueryExecutor` 类，解除核心执行引擎对 `openpyxl` 与 `csv` 模块的直接依赖，并保留原有模块级 `execute_*` 兼容函数。

### 4. 收敛 `EvalContext` 与 AST/求值公开接口（`txtsql/ast.py`, `txtsql/evaluator.py`, `txtsql/parser.py`）
- 在 `ast.py` 统一定义 `contains_aggregate()` 与 `collect_non_agg_columns()`，`parser.py` 与 `executor.py` 共同复用，消除重复遍历实现。
- 在 `evaluator.py` 引入不可变 `EvalContext`（封装 `table_defs`、`subquery_exec`、`agg_eval`、`outer_row`、`valid_single_qualifier`，提供 `with_agg()` / `with_outer()`），将递归参数由 6 个收口为 1 个。
- 将 `resolve_column`、`to_bool`、`is_number`、`to_decimal` 提升为清晰公开接口，彻底消除跨模块私有函数导入。
